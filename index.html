02 / Case Release orchestration

I turned a bare GitLab board into a release system.

The board is the trigger. The ticket carries the state.

A refusal is recoverable. A double deploy is not.

Before

Approvals lived in chat. Release state lived in one person’s head. Deploys were triggered from a terminal.

The move

Engineers move a card. Branches, merge requests, scans, approvals, deploys and audit comments follow. Every result is written back into the ticket.

The result

Deploy, quality gate and zero critical findings must agree, or the release is blocked rather than queued.
